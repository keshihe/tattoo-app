# 本地纹身图像分析优化设计

## 目标

在不上传客户照片、不接入付费接口的前提下，降低四类误判：清洗干净仍报有颜色、无红色却报红色、小面积被报为大面积、疤痕或脱色被报为正常。结果只用于客户初步了解，无法确认时必须保守提示。

## 约束与现状

- 应用是单文件静态网页：`src/index.html` 内含样式和脚本。
- 当前分析在浏览器 Canvas 上执行，没有云端 AI。
- 当前流程使用固定 HSV 阈值、最大皮肤连通区域和全局像素占比。
- 客户照片只保留在浏览器内存中，不新增网络上传。
- 不引入需要训练或下载的大型模型；保持现有免费部署方式。

## 方案

采用保守的多阶段本地分析：

1. **照片质量与场景检查**
   - 保留最大皮肤区域，但统计皮肤覆盖率、边缘背景比例和多个明显非皮肤区域。
   - 对含手机屏幕、衣物、多人或明显对比图的照片标记为“背景复杂”，继续给出结果但降低置信度并提示重拍。

2. **局部皮肤基准**
   - 使用 ROI 内的中位亮度、色度和局部窗口基准，不再用整张照片的单一平均值。
   - 过滤高光、衣物、背景和孤立噪点，避免肤色暖色被当成红色色素。

3. **色素候选区域**
   - 黑灰色素必须同时满足相对周围皮肤明显变暗、局部对比稳定、邻域有连续像素。
   - 彩色色素必须相对周围皮肤有稳定色度差，并且形成达到最小面积的连通区域。
   - 红色采用更高的色度、面积和连通性门槛；少量红色噪点不得生成“红色”标签。
   - 过滤后再计算颜色占比，确保颜色比例的分母是有效色素区域。

4. **面积判断**
   - 同时使用有效色素像素占比和主要连通区域包围盒占比。
   - 对零散噪点、小范围残留和背景阴影使用“几乎无/小面积”；只有主体区域同时达到像素和空间阈值时才显示较大面积。
   - 结果文案明确为“照片中覆盖范围”，避免让客户误解为身体部位真实面积。

5. **疤痕与脱色判断**
   - 将“高亮”从疤痕判据中移除为单独证据，必须结合局部亮度偏差、低色度、纹理/边界连续性和有效区域面积。
   - 疤痕或脱色只输出“疑似疤痕/色差”或“疑似脱色”，不输出医学诊断。
   - 无足够证据时输出“未见明显异常，照片无法完全判断”，不把“分析不到”简化成“正常”。

6. **清洁结果与不确定性**
   - 只有在有效色素区域达到最低稳定证据时才显示颜色和密度。
   - 没有稳定色素时显示“未检测到明显纹身色素 / 色素已基本清除 / 几乎无”。
   - 复杂背景、皮肤区域过小或检测证据冲突时显示“结果仅供参考，请按拍摄建议重拍”。

7. **客户提示**
   - 在上传区域补充单张、近距离、自然光、纹身居中、无遮挡的拍摄建议。
   - 不改变现有跳过照片和继续评估流程。

## 数据接口

保留 `analyzeTattooImage(dataUrl)` 的调用方式，返回现有字段，并增加：

- `confidence`: `'high' | 'medium' | 'low'`
- `sceneWarning`: `string | null`
- `evidence`: `{ inkPixels, inkCoverage, dominantComponentCoverage, redCoverage, scarEvidence }`

现有 `colorType`、`densityLabel`、`coverageLabel`、`skinCondition`、`difficultyMod` 继续供结果页面使用，避免改动问卷和评分流程。

## 测试设计

- 将纯像素判定和标签映射抽成无 DOM 的小函数，使用 Node 内置 `node:test` 测试。
- 先写失败测试覆盖：全皮肤/清洁图无颜色、肤色暖色不报红色、孤立红点不报红色、小连通区域不报大面积、稳定暗色区域报黑灰、低亮度连续色差报疑似脱色/疤痕、复杂场景降低置信度。
- 使用用户提供的 7 张样本做浏览器冒烟验证，检查结果页面不报红色、不把前三张报大面积或正常异常，并确认第 4/7 张可保留红灰残留，第 5/6/8 张不会因背景直接崩溃。
- 所有测试和构建都在完成实现后重新运行；不改变无关的 UI 和业务逻辑。

## 非目标

- 不承诺替代纹身师或医生判断。
- 不新增云端识别、账号、服务器或付费服务。
- 不在没有标注数据的情况下声称使用机器学习模型。
